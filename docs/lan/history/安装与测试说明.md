# 铁底湾的回响 IV · 局域网掷骰交接 / 右侧规则 / CPU RDSEED（实验升级 v2）

适用于 `wmfc7/iron-bottom-sound` 的 `online` 分支，特别针对此前已安装的 `IBS_LAN_INTERACTIVE_DICE_V1` 实验补丁。**不会改动原版 `engine.py`，不会主动清理任何 SQLite 存档或房间凭证。**

## 已修复与新增

1. 精确识别炮击**命中由攻击方**投掷、炮击**毁伤由受击方**投掷；鱼雷**命中由发射方**投掷、鱼雷**毁伤由受击方**投掷。火灾/故障/碰撞按涉事舰船所有方分配。通过 `get_player()` 的原有票据身份控制点击权限，不允许客户端直接设置侧别。
2. 原版 `/api/.../orders` 在封存成功后，改为**服务器后台**执行 `reconcile_once()`，不把漫长的掷骰过程绑在浏览器的订单提交响应里；骰子工作线程对 HTTP 取消使用 `asyncio.shield`，不会仅因为用户刷新网页就抹掉待投骰。
3. 中央页面顶部大字显示“轴心国玩家投掷 / 同盟国玩家投掷”；下面显示具体舰船、检定类型、回合/阶段；右侧显示从当前引擎 `rules` 对象读取的规则表；揭晓后高亮实际对应的**修正后判定行**。不认识的特殊场景显示“规则表不可用”，不编造结果。
4. 新增 Windows x64 CPU `RDSEED`（条件化硬件熵）/`RDRAND`（CPU 硬件 DRBG）原生 DLL 源码和构建脚本。默认 `cpu_rdseed`；CPUID 不支持、DLL 缺失或硬件调用失败时明确报错，**不会自动切换为软件伪随机数**。使用拒绝采样将字节无偏映射到六面骰。
5. 动画骰面循环仅为**固定序列视觉动画**，不会成为真实骰点来源。每个请求唯一 ID、单次消费、服务器审计 JSONL。

## 重要限制

- 原引擎目前仍以“种子 + 随机数消费计数器”实现确定性重放。改为 CPU 硬件掷骰后，旧式重放不能单靠种子还原这些骰点。服务器会记录 `backend/lan-dice-audit.jsonl`，**但尚未把这份审计日志整合进原版 replay 的强一致验证**。不建议用于需要官方可审计回放的比赛。
- 当前引擎在 HTTP 同步的阶段内计算；本实验版可以应对**浏览器请求取消**，但无法在**主机进程退出/断电**时从某一颗骰子原地恢复裁决。请先在测试房间试用。
- 本补丁展示的具体舰名、目标排水量级可能暴露战争迷雾。默认按使用需求向双方显示详细判定；如需隐匿非投骰方的舰名和针对性表格，启动前设置 `IBS_DICE_REDACT_OPPONENT=1`。这是 UI 保密处理，不代替完整的敌情审查。
- 针对 `online` 当前引擎中能明确定位的判定，显示准确规则表。少数未知调用位置/想定特例会降级为“规则表不可用”；**规则计算本身仍由原引擎处理**，不能认为已逐条覆盖全部想定。
- RDSEED 是 CPU 提供的经条件化硬件熵输出；无法仅从一串结果证明它“数学上绝对随机”。RDRAND 使用 CPU 硬件熵支持的 DRBG，**不是每次直接读取未经加工的原始物理噪声**。与 `secrets`/OS CSPRNG 是不同随机源。

## Windows 安装（主机电脑执行）

### 1. 备份

停止所有正在运行的 LAN 服务（终端 `Ctrl+C`），不要双击“新建联机房间”。在源码根目录 PowerShell 执行：

```powershell
cd "C:\Users\19195\Desktop\iron-bottom-sound"
Copy-Item .\lan_server.py .\lan_server.py.pre-dice-v2.bak
Copy-Item .\lan_dice.py .\lan_dice.py.pre-dice-v2.bak
Copy-Item .\lan_dice_client.js .\lan_dice_client.js.pre-dice-v2.bak
Copy-Item .\backend\lan-duel-room.json .\backend\lan-duel-room.json.pre-dice-v2.bak
```

如某文件尚不存在，可跳过该行。强烈建议单独备份整个 `backend` 存档目录；绝对不要随意删除数据库。

### 2. 解压

将 ZIP 里所有文件解压进游戏根目录，覆盖旧版 `lan_dice.py` 和 `lan_dice_client.js`。不用覆盖你的 `lan_server.py`，它由下面的升级程序按源码锚点修改。

### 3. 安装网关升级

```powershell
python "升级交互骰子v2.py"
python -m py_compile lan_server.py lan_dice.py
```

升级程序为 `lan_server.py` 再创建一份带时间戳的 `.bak` 文件。如果当前源码结构不符合预期会拒绝修改，不会强行改写。

### 4. 编译 CPU 原生随机数源

安装 Microsoft **Visual Studio Build Tools 2022/2026** 的 **Desktop development with C++** 工作负载，选择其 **x64 Native Tools Command Prompt**。然后在该窗口执行：

```cmd
cd /d C:\Users\19195\Desktop\iron-bottom-sound
build_cpu_rng.bat
```

应在根目录生成 **`ibs_cpu_rng.dll`**。不需要将 DLL 上传给任何人。它必须由你信任的源代码本地编译，不能随便下载不明来源的同名 DLL。

### 5. 主机上检查实际硬件支持

在新开的 PowerShell 执行：

```powershell
cd "C:\Users\19195\Desktop\iron-bottom-sound"
python -c "from lan_dice import RandomSource; print('CPU RDSEED test:', RandomSource('cpu_rdseed').dice(2))"
```

看到 `[1..6,1..6]` 范围内的两个数字才表明 DLL 已被正常调用。这个冒烟测试**不能证明随机质量**，只证明 CPU 指令接口可以读取数据。若明确提示 CPU 不支持 RDSEED，可自行判断是否接受 `cpu_rdrand`：

```powershell
python -c "from lan_dice import RandomSource; print('CPU RDRAND test:', RandomSource('cpu_rdrand').dice(2))"
```

如果你坚持只允许 RDSEED，**不要设置 `cpu_rdrand` 或 `os_csprng`**。

### 6. 启动旧联机房间

```powershell
$env:IBS_DICE_SOURCE="cpu_rdseed"
python lan_server.py
```

或双击 `启动联机骰子CPU-RDSEED.bat`。不要运行旧的系统安全随机数测试启动脚本（它会强制设置 `IBS_DICE_SOURCE=os_csprng`）。不需要重建 React，因为骰子界面从 LAN 网关加载 `lan_dice_client.js`。

## 联机检查

1. 两台电脑使用**原来的邀请链接**进入，创建测试对局，不要重置正式战役。
2. 让双方都封存炮击或鱼雷计划。
3. 第一颗为炮击命中时，攻击方看到可点击按钮，另一方看到灰色“等待指定玩家投掷”；顶端显示正确阵营。
4. 投掷后双方应看到滚动动画和一致的结果，右侧表格对应行高亮；接下来需要受击方骰点时**点击权限必须转给受击方**。
5. 故意刷新双方浏览器，检查当前请求 ID/结果可恢复；验证重复点击得到 HTTP 409，错误阵营得到 HTTP 403。
6. 检查 `backend/lan-dice-audit.jsonl` 是否记下每颗骰子，字段 `source` 应为 `cpu_rdseed`。**不要在待投骰/裁决进行中强制结束主机进程。**

## 故障排查

- `找不到 ibs_cpu_rng.dll`：用 **x64 Native Tools Command Prompt** 运行 `build_cpu_rng.bat`，不要只在普通 PowerShell 运行 `cl`。
- `CPU不支持 cpu_rdseed`：检查处理器及 BIOS/虚拟机是否暴露 RDSEED 指令。若仅支持 RDRAND，须明确选择另一种硬件模式，不能称等同 RDSEED。
- `不能投骰`：两方分别查看 `http://主机IP:8765/lan/dice/state`，比对 `owner`、`status`、`may_roll`、`seq` 和 `error`；注意 **每一方的 `may_roll` 应不同**。如果看到某一方 `waiting` 且 `may_roll=true` 但按钮没亮，请按 `Ctrl+F5` 清浏览器脚本缓存。
- `calculating` 持续很久：在主机终端找 `[LAN DUEL]` 或 `[LAN DICE]` 错误，注意可能是原规则引擎阻断，不要重复强推。
- 不希望对方看到隐藏舰名：运行前设置 `$env:IBS_DICE_REDACT_OPPONENT="1"`，再启动服务器。
