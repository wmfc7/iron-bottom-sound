# 铁底湾 IV · `online` 分支交互式双人掷骰实验补丁

适用目标：<https://github.com/wmfc7/iron-bottom-sound/tree/online>

> **实验版，不要直接用于唯一存档。** 本补丁已通过模拟 FastAPI/规则引擎测试，但当前环境无法下载并运行整份在线分支源码，因此未完成真实战局端到端验收。原版依赖随机种子的确定性回放，在启用硬件/OS 随机数后不再按旧的 seed 机制复现。**没有实现完整的骰点事件回放以及崩溃中断后的事务级恢复**。服务器在等待玩家骰点期间崩溃，可能必须从上一已保存阶段重新开始；不要在此时关闭程序。

## 补丁内容

- `lan_dice.py`：只拦截 LAN 网关执行 `/advance` 时的引擎 `_roll_d6` / `_roll_2d6` / `_roll_d66`，保留原版所有规则查表与状态计算；使用 `ContextVar` 在独立线程中等待玩家点击。
- `lan_dice_client.js`：双方游戏页中央显示骰子；发起点击的玩家有按钮；双方看到动画，服务端揭晓后显示相同点数；动画的点数不参与判定。
- `install_online_dice.py`：有锚点数量检查；只修改根目录 `lan_server.py`，自动备份；不改动 React 源码和原版 engine.py。
- `test_online_dice.py`：权限、格式、骰点等待、API 线程传递、HRNG 管道、安装脚本检查。

## 安装

1. 关闭现有联机服务器（服务器窗口 `Ctrl+C`）；备份整个 `backend` 目录和你当前的 `lan_server.py`，特别是 SQLite 游戏存档及 `backend/lan-duel-room.json`。不要发送邀请令牌给其他人。
2. 从 GitHub 获取 **`online`** 分支。**不要把本补丁装到 `main` 分支或旧版 v2 网关。**
3. 将补丁 ZIP 内的 `lan_dice.py`、`lan_dice_client.js`、`install_online_dice.py` 放到游戏根目录（与 `lan_server.py` 同级）。
4. 在 Windows PowerShell 中运行：

```powershell
cd "C:\Users\19195\Desktop\iron-bottom-sound"
python install_online_dice.py
python -m py_compile lan_server.py lan_dice.py
```

如果出现“源码与 online 分支不匹配”，补丁会拒绝覆盖，请提供当前 `lan_server.py` 以重新适配。成功时留下 `lan_server.py.before-interactive-dice.bak` 供恢复。**无需再运行 React 构建**，因为骰子 JS 由联机网关加入现有游戏 HTML。

## 随机数的关键说明

本补丁有两种**明确区分**的随机数源：

- 默认 `IBS_DICE_SOURCE=hrng`：**严格物理 HRNG 模式**。要求 `IBS_DICE_HRNG_PATH` 指向运营者已核验的、能够输出原始随机字节的*实时设备流*（例如某些 Linux `/dev/hwrng` 设备）。如果没有此流，服务器会**拒绝启动**，不会偷偷降级到伪随机数。设备必须确保自身熵质量；读取前台驱动的字节流并不自动证明它是真正的物理 TRNG。
- 显式 `IBS_DICE_SOURCE=os_csprng`：通过 Python `secrets.randbelow(6)` 使用系统 CSPRNG。**不等于可验证的物理 HRNG**，只是给没有硬件的电脑做联机功能测试。它不同于原版的可重现 `random.Random(seed)`。

无偏映射：外置 HRNG 输出原始字节时，只接受 `0..251`，把字节 `% 6 + 1` 得到 1..6；`252..255` 丢弃，消除模 6 映射偏差（前提是原始字节均匀）。

**Windows 没有跨所有硬件厂商通用的“读取物理 HRNG”路径**。你需要先确认所用 USB/PCIe/主板 TRNG 的型号、驱动和官方输出协议。本补丁提供通用字节流读取接口，但尚未为特定 Windows 硬件驱动编写适配器；不能声称当前普通 Windows 电脑已经符合物理 HRNG 要求。

### 先测联机交互功能（非物理 HRNG）

在 **同一个** PowerShell 窗口执行：

```powershell
$env:IBS_DICE_SOURCE = "os_csprng"
python lan_server.py
```

双方用原邀请链接进入正在进行的游戏，任意需要投骰的阶段，双方屏幕中央会同时出现骰子，只有授权阵营能够点击。**首次请新建测试对局，不要用唯一的正式对局。**

### 在已经连接并验证真实硬件随机数设备后

如果厂商驱动提供可直接读取原始随机字节的设备流，可在 PowerShell 中明确配置：

```powershell
$env:IBS_DICE_SOURCE = "hrng"
$env:IBS_DICE_HRNG_PATH = "由厂家驱动提供的真实原始字节设备路径"
python lan_server.py
```

上面的路径**只是占位说明**，不是可直接执行的 Windows 设备地址。请勿将普通磁盘文件、文本日志、`/dev/urandom`（OS CSPRNG）假装成 HRNG。

## 设计说明

- 显示数据通过 `GET /lan/dice/state` 300ms 轮询；仅连接到本游戏的玩家可访问。
- 掷骰通过 `POST /lan/dice/roll`，沿用原网关 Cookie 阵营令牌和 Origin 检查。必须带有当前 roll ID、由拥有权限的玩家提交；客户端完全不能指定骰面数字。
- 服务端收到点击后生成随机数，在约 2.2 秒动画期结束时才公开点数，再保留结果约 1.5 秒；每颗骰子只被使用一次。
- 同一时刻只执行一个 `/advance` 裁决；所有实际规则计算依旧在原版 Python 引擎完成。
- 裁决事件的通用归属基于调用处攻击舰、目标舰等局部对象；没有可靠归属的中立判定暂由轴心国玩家代投。**此归属规则尚需用所有剧本逐项验收**。
- 双方都能看到“有某项骰点需要投掷”及归属阵营，这种设计可能泄露某个隐藏事件的存在，但不会发送隐藏舰船名字、坐标或对手密令。
- 骰点日志写到 `backend/lan-dice-audit.jsonl`。该日志用于核对，不等于防篡改硬件证明。

## 重要限制

1. **旧版按种子确定性回放可能不一致。** 随机骰点实际记录在 JSONL 中，但尚未将其接入规则引擎的完整回放执行器。需要后续专门实现 replay tape、版本校验和逐事件恢复才能称为可审计闭环。
2. 当前技术路线是进程内线程暂停，**不支持在等待某颗骰子期间重启服务器并从精确断点恢复**。请使用新测试存档；不要在掷骰进行中重启、手动重试、修改规则源码。
3. 不保证所有特殊剧本掷骰都能自动判断最合适的投掷方，需逐一进行规则审计，尤其是增援、天气和特殊毁伤。
4. 对手由于窗口被浏览器后台限速，可能错过短暂的揭晓显示。可以通过后端审计日志核对；正式版应引入双方确认/重连补偿协议。
5. **完整代码未在真实 online 分支 Windows 环境联调**。先测试小规模场景、双方是否看到相同骰子、是否能继续阶段，再逐步扩大。

## 恢复原版联机

关闭服务器，把游戏根目录的 `lan_server.py.before-interactive-dice.bak` 复制回 `lan_server.py` 覆盖，恢复原版局域网交互。不要删除任何数据库、房间文件。辅助 `lan_dice.py` 和 JS 可以保留不用。
