# EasyTier 双击入场、选择阵营与大厅存读档

本变更仅修改双人联机网关、大厅与加入流程；不修改规则引擎、单机前端、骰子/CPU RDSEED 模块。

## 房主

1. 两台机器均加入**同一个 EasyTier 网络**；房主原样双击 `EasyTier双人联机.bat` 并选择“恢复房间”或“新房间”。房主应先关闭单机服务，确保 `8765/TCP` 只绑定 EasyTier 虚拟 IPv4。
2. 启动成功后会在**游戏项目目录的上一级**自动生成 `铁底湾-双击加入联机大厅.url`（示例：项目在桌面 `iron-bottom-sound/`，文件生成在桌面）。
3. 将这个 `.url` 文件**私下**发给另一名玩家；房主也双击同一个文件。此文件是凭据，**不能提交到 GitHub、发到群聊或公开**。
4. 双方浏览器选择空闲的“轴心国／同盟国”，进入原有共同准备大厅。阵营会保持在同一个浏览器的 Cookie 中，房主重启网关后仍可进入原阵营。
5. 如果房主 EasyTier 虚拟 IP 改变，重新运行主机脚本，再发送新生成的 `.url`。

## 存档与读档

- 任一已进入房间的玩家，可点击“将当前对局存档到主机”。存档包含完整引擎历史，由房主保存在 `backend/lan-saves/`，**不会被网络接口下载给客户端**；API 仅返回名称、时间、想定、回合和阶段。
- 双方都可以从大厅存档列表中选择并“确认读取此存档”。读档必须两方确认**同一个存档**，网关才调用原版受校验的 `/games/import` 接口，新建对局 ID，并让双方进入恢复的对局。
- 读档保留旧对局与存档，不覆盖原对局的 SQLite 记录。不要手工把游戏数据库、存档、房间 JSON、`.url` 分享到公开位置。
- 若存档处于一方已封存而另一方未封存的中间状态，恢复后本阶段的“撤回封存”可能因旧游戏专用检查点不再适配而不可用；建议在双方尚未封存的新阶段存档。其他已保存游戏阶段状态仍由原版 API 导入。

## 安全边界与常见问题

- 每个阵营只允许一名玩家认领；打开同一共享文件不能覆盖已认领的阵营，旧浏览器 Cookie 可用于恢复进入。
- 共享 `.url` 的凭据只在 URL `#` 片段中，浏览器会立即清除地址栏片段并以 POST 认领，避免加入凭据作为请求 URL 出现在服务器访问日志中。
- 仍兼容此前按阵营分开的私有邀请链接；**新玩家请优先使用共享入口文件**。
- 玩家需要使用与第一次认领相同的浏览器/浏览器配置文件；不要清理该站点 Cookie。若电脑或浏览器彻底丢失，需房主在停止服务器后重新创建房间（重置双方座位凭证）。**创建新房间不会删除旧对局与主机存档**，但会轮换共享入口密钥。
- 如果 `.url` 双击无法打开：检查 EasyTier 互联、房主是否仍启动、TCP 8765 是否可达、Windows 防火墙和房主的 EasyTier IP；使用 `Test-NetConnection 房主EasyTier_IP -Port 8765` 诊断。
- 只在可信 EasyTier 网络使用，**不要公网映射**主机游戏端口，且无需启用 EasyTier 的 UDP 广播转发。浏览器通过主机的确定 URL 建立 TCP 连接。

## 验证

安装后测试顺序：

1. 房主启动并生成 `.url`，确保地址是房主 EasyTier IPv4，不是 `127.0.0.1` 或物理网卡地址。
2. 两台电脑双击同一 `.url`，分别认领阵营；尝试在第三个全新浏览器认领已占用的阵营应失败。
3. 双方共同启动对局；一方在大厅存档，另一方刷新列表后能看到摘要。
4. 一方申请读档时**不能**立即改变当前对局；另一方确认同一个存档后，双方切换到新恢复的对局。
5. 重启房主网关后检查现有房间、座位、旧存档仍可恢复。

## 已知验证限制

源码包缺少项目完整的规则 CSV、前端生产构建和实际 Windows/EasyTier 对端，因此无法在交付环境运行完整原版引擎／Windows 真机双人联机验收。已通过隔离的 FastAPI 路由、会话、双边读档和磁盘存档专项测试。
