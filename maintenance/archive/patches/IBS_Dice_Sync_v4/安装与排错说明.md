# 铁底湾 IV · 骰子同步 v4 修复版

针对两端出现“超过 5 秒未收到新的服务器状态”、一侧停留滚动而另一侧已揭晓的问题。基于此前交付的 `lan_dice.py` v3，专为 wmfc7/iron-bottom-sound 的 online 分支联机网关增量升级。

## 修复

- 原 v3 在 `threading.Condition` 全局锁内调用 `_persist()`，其中 `os.fsync()` 可能被 Windows 防病毒程序、同步盘或磁盘 I/O 延迟拖慢。v4 先记录 `committing` 状态，释放锁后写审计；**写入成功之前不会把骰点交还规则引擎**。
- 原 v3 在持有同一个锁时调用 CPU 随机数 DLL。v4 用 `generating` 状态预留唯一请求，在锁外取数，再加锁提交；其他玩家不能重复投掷。
- `/lan/dice/state` 不再在异步事件循环线程上等待同步锁，而是通过 `asyncio.to_thread` 读取；增加 `/lan/dice/health`（同样必须先登录房间）。
- 保留双端 ACK，但 ACK 不再是推进的必要条件：展示时间达到设置的上限后自动继续；默认不超过大约 4 秒（此外仍有 2.4 秒骰子滚动动画）。这无法保证断网端一定看过该结果，但避免无限等待。
- 保留 RDSEED/RDRAND `RandomSource` 原逻辑，不静默降级为 Python `random.Random`。同时保留规则表和骰点结果高亮。

## 安装前

**不要在一颗骰子仍待投掷或正在裁决时直接重启服务。** 当前原版与实验骰子补丁没有持久化“在裁决函数中途暂停”的完整状态；如果后台真的卡死并且只剩重启一条路，先备份以下文件，接受未完成阶段可能需要重新进入测试局：

- `backend/lan-duel-room.json`（含票据；不要上传公开网络）
- 原版 SQLite 存档
- `backend/lan-dice-audit.jsonl`
- 主机控制台日志

备份后停止服务；不要运行“新建房间”。

## 安装（Windows）

1. ZIP 内含文件夹 `IBS_Dice_Sync_v4`，整个文件夹解压到 `C:\Users\19195\Desktop\iron-bottom-sound` 下。
2. 打开 PowerShell：

```powershell
cd "C:\Users\19195\Desktop\iron-bottom-sound"
python .\IBS_Dice_Sync_v4\Install-Dice-Sync-v4.py
```

安装器首先备份现有 `lan_dice.py` 和 `lan_dice_client.js` 到 `backups/dice-sync-v4-日期时间/`；只覆盖这两个文件，不改 `lan_server.py`、原版引擎、战报和房间存档。安装器本身是纯 ASCII 源码，不再受 Windows PowerShell 5.1 读中文脚本编码的问题影响。

3. 语法检测（正常应无报错）：

```powershell
python -m py_compile .\lan_dice.py
node --check .\lan_dice_client.js
```

4. 重启服务器，必须继续使用一进程一个 Uvicorn worker：

```powershell
$env:IBS_DICE_SOURCE = 'cpu_rdseed'
python .\lan_server.py
```

5. 双方浏览器按 `Ctrl + F5` 刷新，保留自己的阵营邀请 cookie。

## 如何判断修复已加载

两名玩家各自在已登录的浏览器中访问：

```
http://192.168.1.3:8765/lan/dice/health
```

以上 IP 用主机实际 IP 替换。正常应能看到 `"protocol": 4`，并且 `"worker_busy"`、`"status"`、`"seq"` 会随判定变化。如果这里也持续无法打开，请检查主机 Python 进程和主机终端；不是单纯动画问题。

状态可能为：`waiting`（待授权玩家点击）、`generating`（读取 RDSEED）、`rolling`（双方动画）、`revealed`（结果揭晓）、`committing`（审计写入）或 `calculating`（引擎处理其他判定）。

若 `committing` 长期持续，说明审计文件/磁盘 I/O 仍存在问题；不能跳过审计强制推进。

## 自动化测试

```powershell
python -m pytest .\IBS_Dice_Sync_v4\test_dice_v4.py -q
```

该测试使用固定的**模拟**骰子输入；不检验 Windows DLL 本身。请另在 Windows 上用真正 RDSEED 配置实测，不要将模拟输入用于正式对局。

## 限制

这是补丁的模拟环境验证，不代表已经在两台 Windows 浏览器与完整游戏源码上完成端到端验收。当前骰点不具备可从进程崩溃时精确恢复到裁决函数内部的能力；旧的确定性重放也不能单纯依赖种子再现 RDSEED 掷骰。网络断开期间可能漏看单条结果，最终以服务端审计日志为准。不要用于唯一的正式存档测试。
