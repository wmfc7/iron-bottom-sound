# 铁底湾 IV · 骰子同步/交接稳定性修复 v3

## 适用范围

适用于已经安装 **交互式掷骰 v2** 的 `wmfc7/iron-bottom-sound` `online` 分支局域网网关。补丁只修改游戏根目录下的 `lan_dice.py` 和 `lan_dice_client.js`；不会修改原版 `engine.py`、`lan_server.py`、房间凭证、规则表或 SQLite 存档。原有 CPU RDSEED/RDRAND DLL 不必重编译。

## 为什么要修

v2 前端的 `/lan/dice/state` 轮询没有超时：有一个请求卡住时，`inFlight` 会一直保持 true，另一边早已进入新的掷骰序号，而本地依然显示旧结果。`/lan/dice/roll` POST 如果长期不返回，客户端也会一直显示“已发送，等待服务器”。v2 引擎固定展示结果约 2.2 秒后就切换下一判定，没有两端收悉确认。

## 变化

1. 每次服务器掷骰结果 `revealed` 后，两台已授权浏览器会分别发送 `/lan/dice/ack`，确认看到了当前骰点 ID。服务器在至少展示 2.2 秒之后、收到双方确认后才允许引擎继续到下一颗骰子。若一端断网，最多等待约 6.6 秒，自动放行以免死锁。设置 `IBS_DICE_ACK_TIMEOUT` 可调整该时间（必须 ≥ 2.2 秒）。
2. GET 状态和 POST 投骰/确认都设置请求超时；超时后自动恢复查询，**不自动重新投骰**；界面显示连接异常/可能过期，禁用旧结果对应的操作按钮。
3. 浏览器通过服务器发送的时间戳驱动骰子动画，减小两端的动画起始差异；最终骰面继续只由服务器 CPU RDSEED/RDRAND 决定。
4. 在旧请求失败或延迟期间，如果服务器已转到新的掷骰 ID，本地立即清空旧的按钮锁定和动画状态，避免把上一颗的结果当成下一颗。
5. 服务端防重复投骰和身份验证仍有效；确认接口必须携带当前登录阵营的授权 Cookie。

## 安装

1. 正在裁决/待投骰时**不要直接关闭主机**。最好先完成当前阶段或在新测试房间测试；停止服务器前备份 `backend` 存档目录和 `backend/lan-duel-room.json`。
2. 将此 ZIP 解压出的 `IBS_Dice_Sync_v3` **文件夹**复制到游戏根目录，使 `lan_server.py` 和 `IBS_Dice_Sync_v3` 文件夹处于同一层。
3. 停止服务（主机的 PowerShell 中 Ctrl+C），进入游戏根目录并执行：

```powershell
cd "C:\Users\19195\Desktop\iron-bottom-sound"
powershell -NoProfile -ExecutionPolicy Bypass -File .\IBS_Dice_Sync_v3\安装骰子同步修复v3.ps1
```

4. 照原本方式启动联机服务器，保留 CPU 硬件随机数设置：

```powershell
$env:IBS_DICE_SOURCE = 'cpu_rdseed'
python lan_server.py
```

5. 两方在游戏浏览器使用 `Ctrl+F5` 强制刷新，保证读取新版 `/lan/dice/client.js`。

## 验收建议

- 两方同时打开 `http://主机IP:8765/lan/dice/state`，比较 `id`、`seq`、`status`：这些字段应相同；`may_roll` 只有有权限的一方为 true。
- 对同一颗骰子双方都能看到动画和最终骰点；两方确认后，才显示下一次判定。
- 在其中一方按 `F12` 网络面板模拟网络中断，另一方的游戏会在确认超时后继续；恢复网络的一方能自动读取新序号，而不会永远停在旧的“结果已揭晓”。
- `backend/lan-dice-audit.jsonl` 继续记录真正的硬件骰点；确认消息**不会再生成新的随机数**。

## 明确限制

- ACK 机制无法让两台设备在网络故障时绝对同时显示每个画面，也不能取代长期断线的重连和可靠回放；发生掉线时会优先保障对局可以继续。
- 这是针对你发送的截图与 v2 补丁源码制定的修复；已经通过 Python 模拟接口测试，但**没有在你那两台 Windows 电脑上完成实机验收**。
- 不要在已经有骰子处于 `waiting` / `rolling` / `revealed` 的过程中重启 Python 服务器；旧实验系统的引擎裁决不是崩溃事务式恢复，重启可能影响未完成阶段。
- 如果无法修复，请分别保留两边 `/lan/dice/state` 的响应（不要提交邀请码/票据）、浏览器 F12 Network 中失败的 `/lan/dice/state` 或 `/lan/dice/roll` 请求状态，以及主机 `[LAN DICE]` 日志。
