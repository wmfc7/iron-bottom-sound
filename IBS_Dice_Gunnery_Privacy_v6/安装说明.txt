铁底湾的回响 IV / online LAN 骰子、隐私与炮击战果 v6（实验版）
========================================================

本补丁基于用户正在使用的 online 联机流程与之前的 v5 骰子文件。
不能单独替代游戏。未改变 CPU RDSEED 的取数 DLL 和原版战斗规则。

改动：
1. 炮击命中 D66 与逐发炮击毁伤 D66 均由攻击舰所属阵营投掷。
   鱼雷、火灾和碰撞判定权限仍沿用之前的规则。
2. 骰子页面的“详细信息”由服务器按 Cookie 绑定的阵营过滤：
   自己的舰名与 ID 正常显示，对方舰名与 ID 显示 ***。
   对方私有 GF、排水量级、命中修正等表格参数不发送到浏览器。
   双方仍可看到本次判定的理由、骰型以及公开的原始骰点。
   这套屏蔽是后端裁剪，不是客户端 CSS 隐藏。
3. 投骰层右上角有“收起”；收起后右上角有“展开投骰”，
   可以看到背后的战场页面。若新骰点轮到本方，自动展开。
4. 两方封存炮击订单后：原版引擎完成本阶段炮击 ->
   暂停自动推进 -> 两个浏览器打开原版 GunneryOutcomeModal（
   根据当前阵营可见 events 汇总的双方炮击及已公开船体损伤）->
   两名玩家点击“确认战果” -> 网关再推进鱼雷效果等后续阶段。
   这一确认状态写在原房间 JSON 中，服务器重启后仍能恢复。

重要限制：
- 请不要在正在等待手动投骰/裁决还没完成时重启服务器。
  当前骰子计算线程仍不能完整事务式恢复。
- 之前的 v5 缓解拥塞机制和原版已有的隐蔽损伤权限仍被保留。
- 原版 GunneryOutcomeModal 按阵营已经公开的事件显示，
  隐藏损伤规则阻止公开的敌方损伤不会被强行展示。
- 需要两位玩家确认炮击战果才能继续；一方掉线时需该方重新登录，
  当前版本没有“跳过对手确认”按钮，以免绕过回合权限。
- 不修改旧存档表结构，仍建议用新的测试局先运行完整炮击回合。
- 当前环境没有可运行的完整 Windows 游戏仓库和 RDSEED DLL，
  这里通过的是本地单元/兼容性测试，而不是双浏览器端到端验收。

安装：
0. 等本次战斗裁决完全结束，关闭联机网关，备份 backend 的
   SQLite、backend/lan-duel-room.json、backend/lan-dice-audit.jsonl。
1. 将 ZIP 内完整的 IBS_Dice_Gunnery_Privacy_v6 文件夹放到游戏根目录：
   C:\Users\19195\Desktop\iron-bottom-sound\IBS_Dice_Gunnery_Privacy_v6\
2. 在 PowerShell 执行：
   cd "C:\Users\19195\Desktop\iron-bottom-sound"
   python .\IBS_Dice_Gunnery_Privacy_v6\Install-IBS-Dice-v6.py
3. 前端原版 App.tsx 也被更新，需要重新编译：
   cd frontend
   pnpm.cmd run build
   cd ..
4. 使用已有 CPU RDSEED DLL 启动：
   $env:IBS_DICE_SOURCE = "cpu_rdseed"
   python lan_server.py
5. 两个不同阵营的浏览器分别 Ctrl+F5 强制刷新。

可验证：
- 打开同一骰点 /lan/dice/state：同盟国浏览器不应看到轴心国舰名，
  轴心国浏览器不应看到同盟国舰名；不能只看 UI，必须核查 JSON。
- 连续开炮，确认攻击方对命中及毁伤均具有 may_roll=true。
- 点击收起，之后点击展开，再继续掷骰，不应改变序号。
- 炮击全部结束后两端应显示原版炮击战果弹窗。
  只在双方点击“确认战果”后继续后续阶段。
- 检查 backend/lan-duel-room.json 中 gunnery_checkpoint 的 acks。
  请不要公开此文件（包含登录/房间信息）。

恢复旧文件：
安装器会创建 ibs-dice-v6-backup-日期时间 文件夹，内含这次
修改前的 4 个源文件。如果新补丁与您本机源码不兼容，请停止服务器，
将备份中的同名文件逐一复制回原位置，并重新运行前端 pnpm.cmd run build。
不要删除 SQLite、审计日志、房间信息。
